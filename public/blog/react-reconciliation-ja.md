# React 調整アルゴリズム

## 概要

Reactの調整アルゴリズム（reconciliation algorithm）は、一般に「ディフィング（diffing）」と呼ばれ、Reactが効率的にDOMを更新できるようにする中核的なメカニズムです。これはReactを高速にし、不要な全体的な再レンダリングを防ぎます。

## 調整とは？

調整は、ReactがDOMのどの部分を更新する必要があるかを判断するプロセスです。コンポーネントの状態またはpropsが変更されたとき、Reactは全体のコンポーネントツリーをすぐに再レンダリングするのではなく、洗練されたアルゴリズムを使用して新しい仮想表現を前のものと比較します。

## 仮想DOM

調整アルゴリズムの詳細に入る前に、仮想DOMを理解する必要があります：

- **仮想DOM**: 実際のDOMのメモリ内表現
- **軽量**: 各仮想要素はJavaScriptオブジェクト
- **バッチ更新**: 変更は効率のためにまとめてバッチされます

## ディフィングアルゴリズム

Reactは2つの主要な仮定を持つディフィングアルゴリズムを使用します：

### 1. 異なるタイプは異なるツリーを生成

2つの要素を比較する場合：
- タイプが異なる場合（例：`<div>` vs `<span>`）、Reactは完全に新しいDOMノードを作成
- これは異なる要素タイプが異なる構造を持つ可能性が高いため

### 2. 安定したキーはコンポーネントの状態を保持

ユニークな`key`プロップを提供することで：
- Reactはどの項目が変更され、追加され、削除されたかを識別できます
- これはリストが適切なコンポーネント状態を維持するために重要です

## 調整の仕組み

### ステップ1: ルート要素の比較

```jsx
// 以前のレンダリング
<div className="greeting">
  <h1>Hello</h1>
</div>

// 新しいレンダリング
<div className="greeting">
  <h1>Hello World</h1>
</div>
```

Reactは両方のルート要素が`div`タイプであることを検出し、同じDOMノードを保持します。

### ステップ2: 子要素で再帰

Reactは子要素の比較を続けます。この場合、すべての`h1`タグが同じタイプなので、Reactは：
- DOMノードを保持
- テキスト内容を比較
- 変更されたテキストのみを更新

### ステップ3: キーを使用したリストの処理

```jsx
// キーなし（効率的でない）
{items.map((item) => <Item>{item.text}</Item>)}

// キーあり（効率的）
{items.map((item) => <Item key={item.id}>{item.text}</Item>)}
```

キーはReactに項目が変更されたことを伝え、コンポーネントインスタンスを再利用し、内部状態を保持できるようにします。

## パフォーマンスの考慮事項

### ベストプラクティス

1. **リストで常にユニークで安定したキーを使用**
   - 配列インデックスをキーとして使用しない
   - データのユニークなIDを使用

2. **コンポーネント構造を安定的に保つ**
   - レンダリング中に新しい関数やオブジェクトを作成しない
   - 必要に応じて`useCallback`と`useMemo`を使用

3. **コード分割と遅延ロード**
   - 大きなバンドルを分割して初期ロード時間を短縮
   - 動的インポートに`React.lazy`を使用

4. **React DevToolsでプロファイリング**
   - プロファイラーを使用して低速なコンポーネントを特定
   - レンダリング時間とコンポーネントの更新を監視

## 一般的な落とし穴

### ❌ インデックスをキーとして使用

```jsx
// これをしないでください
{items.map((item, index) => <Item key={index}>{item.text}</Item>)}
```

リストが再順序付けされたりフィルタリングされたりするときに破綻します。

### ✅ 安定したIDを使用

```jsx
// これをしてください
{items.map((item) => <Item key={item.id}>{item.text}</Item>)}
```

## 高度なトピック: Fiberアーキテクチャ

React 16以降では、調整アルゴリズムはFiberアーキテクチャを使用するように書き直されました：

- **増分レンダリング**: 作業を複数のフレームに分割可能
- **優先度ベースの更新**: 異なる更新は異なる優先度を持つことができます
- **エラーバウンダリー**: レンダリング中のより良いエラー処理
- **並行処理**: 並行機能の基盤

## 結論

Reactの調整アルゴリズムは、インタラクティブなUIの構築を効率的で予測可能にする強力な最適化です。その仕組みを理解することで、より高速なReactアプリケーションを作成し、一般的な落とし穴を避けることができます。

### 重要なポイント

✅ Reactはディフィングアルゴリズムを使用して何が変更されたかを判定
✅ 実際のDOMではなく仮想DOMが比較される
✅ キーはリストパフォーマンスに不可欠
✅ 安定したコンポーネント構造はパフォーマンスを向上
✅ Fiberアーキテクチャは増分レンダリングを有効にする
