# 리액트 재조정 알고리즘

## 개요

리액트의 재조정 알고리즘(reconciliation algorithm), 흔히 "디핑(diffing)"이라고 불리며, 리액트가 DOM을 효율적으로 업데이트할 수 있게 하는 핵심 메커니즘입니다. 이것이 리액트를 빠르게 만들고 불필요한 전체 리렌더링을 방지하게 합니다.

## 재조정이란?

재조정은 리액트가 DOM의 어느 부분을 업데이트해야 하는지 결정하는 과정입니다. 컴포넌트의 상태나 props가 변경될 때, 리액트는 전체 컴포넌트 트리를 즉시 리렌더링하지 않습니다. 대신, 정교한 알고리즘을 사용하여 새로운 가상 표현을 이전의 것과 비교합니다.

## 가상 DOM

재조정 알고리즘을 자세히 알아보기 전에 가상 DOM을 이해해야 합니다:

- **가상 DOM**: 실제 DOM의 메모리 내 표현
- **가볍다**: 각 가상 요소는 JavaScript 객체
- **배치 업데이트**: 변경 사항들이 효율성을 위해 함께 배치됨

## 디핑 알고리즘

리액트는 두 가지 핵심 가정을 가진 디핑 알고리즘을 사용합니다:

### 1. 다른 타입은 다른 트리를 생성

두 요소를 비교할 때:
- 타입이 다르면 (예: `<div>` vs `<span>`), 리액트는 완전히 새로운 DOM 노드를 생성
- 이는 다른 요소 타입이 다른 구조를 가질 가능성이 높기 때문

### 2. 안정적인 키는 컴포넌트 상태를 유지

유니크한 `key` prop을 제공하면:
- 리액트는 어떤 항목이 변경되었는지, 추가되었는지, 제거되었는지 식별할 수 있음
- 리스트가 올바른 컴포넌트 상태를 유지하는 데 중요

## 재조정이 어떻게 작동하는가

### 단계 1: 루트 요소 비교

```jsx
// 이전 렌더링
<div className="greeting">
  <h1>Hello</h1>
</div>

// 새로운 렌더링
<div className="greeting">
  <h1>Hello World</h1>
</div>
```

리액트는 두 루트 요소가 모두 `div` 타입임을 감지하고 동일한 DOM 노드를 보존합니다.

### 단계 2: 자식 요소에 대해 재귀

리액트는 자식 요소 비교를 계속합니다. 이 경우 모든 `h1` 태그가 같은 타입이므로 리액트는:
- DOM 노드를 보존
- 텍스트 내용을 비교
- 변경된 텍스트만 업데이트

### 단계 3: 키를 사용한 리스트 처리

```jsx
// 키 없음 (비효율적)
{items.map((item) => <Item>{item.text}</Item>)}

// 키 있음 (효율적)
{items.map((item) => <Item key={item.id}>{item.text}</Item>)}
```

키는 리액트에게 어떤 항목이 변경되었는지 알려주어, 컴포넌트 인스턴스를 재사용하고 내부 상태를 유지할 수 있게 합니다.

## 성능 고려사항

### 모범 사례

1. **리스트에서 항상 유니크한 안정적 키 사용**
   - 배열 인덱스를 키로 사용하지 않기
   - 데이터의 유니크한 ID 사용

2. **컴포넌트 구조 안정적으로 유지**
   - 렌더링 중에 새로운 함수나 객체 생성 피하기
   - 필요할 때 `useCallback`과 `useMemo` 사용

3. **코드 분할 및 지연 로드**
   - 큰 번들을 분할하여 초기 로드 시간 단축
   - 동적 임포트를 위해 `React.lazy` 사용

4. **React DevTools로 프로파일링**
   - 프로파일러를 사용하여 느린 컴포넌트 식별
   - 렌더링 시간 및 컴포넌트 업데이트 모니터링

## 일반적인 함정

### ❌ 인덱스를 키로 사용

```jsx
// 이렇게 하지 마세요
{items.map((item, index) => <Item key={index}>{item.text}</Item>)}
```

리스트가 재정렬되거나 필터링될 때 깨집니다.

### ✅ 안정적 ID 사용

```jsx
// 이렇게 하세요
{items.map((item) => <Item key={item.id}>{item.text}</Item>)}
```

## 고급: Fiber 아키텍처

React 16+에서 재조정 알고리즘은 Fiber 아키텍처를 사용하도록 다시 작성되었습니다:

- **증분 렌더링**: 작업을 여러 프레임에 걸쳐 분할 가능
- **우선순위 기반 업데이트**: 다양한 업데이트가 다양한 우선순위를 가질 수 있음
- **에러 바운더리**: 렌더링 중 더 나은 에러 처리
- **동시성**: 동시성 기능의 기초

## 결론

리액트의 재조정 알고리즘은 인터랙티브한 UI 구축을 효율적이고 예측 가능하게 만드는 강력한 최적화입니다. 이것이 어떻게 작동하는지 이해함으로써 더 나은 성능의 리액트 애플리케이션을 작성하고 일반적인 함정을 피할 수 있습니다.

### 핵심 요점

✅ 리액트는 디핑 알고리즘을 사용하여 무엇이 변경되었는지 결정
✅ 실제 DOM이 아닌 가상 DOM이 비교됨
✅ 키는 리스트 성능에 필수적
✅ 안정적인 컴포넌트 구조는 성능을 향상
✅ Fiber 아키텍처는 증분 렌더링을 가능하게 함
